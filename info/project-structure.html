📚 Основы Next.js - Теория

Что такое Next.js и зачем он нужен?

Представьте, что React — это конструктор Lego. Вы можете строить из него что угодно, но вам нужно самому решать множество вопросов: как организовать маршрутизацию, как оптимизировать изображения, как сделать сайт быстрым и SEO-friendly.

Next.js — это как готовый набор инструкций и дополнительных деталей к этому конструктору. Он берет React и добавляет:

  • Файловую маршрутизацию — создаете файл, получаете страницу
  • Серверный рендеринг — страницы формируются на сервере для быстрой загрузки
  • Оптимизацию изображений — автоматическое сжатие и lazy loading
  • API Routes — возможность создавать бэкенд прямо в проекте
  • Автоматическое разделение кода — каждая страница загружает только нужный JavaScript

🎓 Теория: React vs Next.js

React (библиотека):

  • Только для создания UI компонентов
  • Рендеринг происходит в браузере (Client-Side Rendering)
  • Требует дополнительных библиотек для роутинга (React Router)
  • Сложнее настроить SEO

Next.js (фреймворк):

  • Полноценный фреймворк с маршрутизацией
  • Может рендерить на сервере (Server-Side Rendering)
  • Встроенная файловая маршрутизация
  • Отличное SEO из коробки
  • Множество оптимизаций производительности

App Router vs Pages Router

В Next.js есть две системы маршрутизации:

⚠️ Важно понимать!

Pages Router (старый подход) — использует папку pages/

App Router (новый подход) — использует папку app/

Наш проект использует App Router — это современный и рекомендуемый подход с Next.js 13+

Ключевые концепции App Router

1. Server Components vs Client Components

🎓 Теория: Server и Client компоненты

Это одна из самых важных концепций в Next.js 15!

Server Components (по умолчанию):

  • Выполняются ТОЛЬКО на сервере
  • Не попадают в JavaScript bundle клиента (меньший размер!)
  • Могут напрямую обращаться к базе данных
  • Не могут использовать хуки React (useState, useEffect)
  • Не могут обрабатывать события (onClick, onChange)

Client Components:

  • Выполняются в браузере
  • Могут использовать все хуки React
  • Могут обрабатывать пользовательские события
  • Нужны для интерактивности
  • Помечаются директивой "use client" в начале файла
// Server Component (по умолчанию)
export default function Page() {
  return <div>Я рендерюсь на сервере!</div>;
}

// Client Component
"use client"; // ← эта директива делает компонент клиентским

export default function InteractiveButton() {
  const [count, setCount] = useState(0);
  return <button onClick={() => setCount(count + 1)}>{count}</button>;
}

2. Файловая маршрутизация

В Next.js с App Router структура папок определяет URL сайта:

app/ ├── page.tsx → yoursite.com/ ├── about/ │ └── page.tsx → yoursite.com/about └── blog/ ├── page.tsx → yoursite.com/blog └── [slug]/ └── page.tsx → yoursite.com/blog/любой-slug

💡 Важные правила:

  • page.tsx — это файл, который становится страницей
  • Папки без page.tsx НЕ создают маршрут
  • [slug] — динамический сегмент (параметр в URL)
  • (folder) — группирующая папка, НЕ влияет на URL

3. Специальные файлы в App Router

Файл Назначение
page.tsx Страница маршрута
layout.tsx Общий макет для страниц (header, footer)
loading.tsx UI состояния загрузки
error.tsx UI состояния ошибки
not-found.tsx UI для 404 страницы
template.tsx Похож на layout, но пересоздается при навигации

4. Layouts (Макеты)

🎓 Что такое Layout?

Layout — это обертка для страниц. Представьте, что у вас есть сайт с header и footer на каждой странице. Вместо того, чтобы копировать их код на каждую страницу, вы создаете layout один раз, и он автоматически применяется ко всем вложенным страницам.

// app/layout.tsx
export default function RootLayout({ children }) {
  return (
    <html>
      <body>
        <Header />
        {children} {/* ← сюда подставляется содержимое страницы */}
        <Footer />
      </body>
    </html>
  );
}

Важно: Layouts НЕ перерендериваются при переходе между страницами! Это улучшает производительность.

✅ Как начать кастомизацию?

  1. Поменяйте тексты — откройте файлы в папке data/
  2. Замените изображения — положите свои файлы в public/img/
  3. Обновите метаданные — в app/layout.tsx измените title и description
  4. Настройте соцсети — отредактируйте data/socials.json
  5. Добавьте резюме — замените public/resume-sample.pdf своим файлом

Как проект работает вместе?

🔄 Поток данных в проекте:

  1. Пользователь заходит на сайт → Next.js загружает app/layout.tsx
  2. Layout оборачивает страницу → применяет шрифты, провайдеры, глобальные компоненты
  3. Загружается страница (например, app/(homes)/home-1/page.tsx)
  4. Страница импортирует компоненты из components/homes/home-1/
  5. Компоненты загружают данные из data/*.json
  6. Изображения загружаются из public/img/
  7. Анимации инициализируются через GSAP и Lenis

Структура папки app/

app/ ├── (homes)/ ← Route Group (группирующая папка) │ ├── home-1/ │ │ └── page.tsx → /home-1 │ ├── home-2/ │ │ └── page.tsx → /home-2 │ └── home-3/ │ └── page.tsx → /home-3 ├── preview/ │ └── page.tsx → /preview ├── layout.tsx ← Root Layout (обертка для всех страниц) └── page.tsx ← Главная страница /

🎓 Что такое Route Groups?

Папки в скобках (homes) — это Route Groups. Они нужны для организации файлов, но НЕ создают сегмент в URL.

Пример:

  • app/home-1/page.tsx → /home-1
  • app/(homes)/home-1/page.tsx → /home-1 (тот же URL!)

Route groups полезны, когда нужно сгруппировать связанные страницы в одной папке, но не хочется добавлять лишний сегмент в URL.

app/layout.tsx — Корневой Layout

D:\3. My Projects\3.Front-end\Nexst.JS\1.blayden\blayden\app\layout.tsx

Это самый важный файл проекта. Он оборачивает абсолютно все страницы сайта.

Что делает этот файл?

  1. Подключает шрифт Urbanist через Google Fonts
  2. Импортирует глобальные стили (CSS файлы)
  3. Настраивает тему (светлая/темная)
  4. Оборачивает приложение провайдерами (Context API)
  5. Добавляет глобальные компоненты (плавная прокрутка, кнопка "наверх")

Ключевые части layout.tsx:

// 1. Импорт шрифта
import { Urbanist } from "next/font/google";

const urbanist = Urbanist({
  subsets: ["latin"],
  variable: "--font-urbanist",  // CSS переменная
});

// 2. Метаданные (SEO)
export const metadata: Metadata = {
  title: "Blayden - Personal Portfolio & Resume React Nextjs Template",
  description: "Blayden - Personal Portfolio & Resume React Nextjs Template",
};

// 3. Скрипт для темы (выполняется до загрузки React!)
const setColorSchemeScript = `
(function() {
  try {
    var scheme = localStorage.getItem('color-scheme') || 'light';
    document.documentElement.setAttribute('color-scheme', scheme);
  } catch(e) {}
})();
`;

// 4. Root Layout компонент
export default function RootLayout({ children }) {
  return (
    <html lang="en" suppressHydrationWarning>
      <head>
        <script dangerouslySetInnerHTML={{ __html: setColorSchemeScript }} />
      </head>
      <body className={urbanist.variable}>
        <PortfolioProvider>
          {children}                {/* ← Сюда подставляются страницы */}
          <LenisSmoothScroll />     {/* Плавная прокрутка */}
          <ScrollTop />             {/* Кнопка "наверх" */}
          <PortfolioPopup />        {/* Модальное окно портфолио */}
          <InitScroll />            {/* Инициализация GSAP анимаций */}
        </PortfolioProvider>
      </body>
    </html>
  );
}

🎓 Что такое {children}?

В React {children} — это специальный prop, который содержит дочерние элементы компонента.

В случае с Layout, {children} — это содержимое текущей страницы:

  • На /home-1 → children будет содержимым app/(homes)/home-1/page.tsx
  • На /preview → children будет содержимым app/preview/page.tsx

🎓 Что такое компонент в React?

Компонент — это переиспользуемая часть интерфейса. Это как кирпичик Lego, из которых строится весь сайт.

Например, кнопка — это компонент. Вместо того, чтобы писать HTML для кнопки каждый раз, вы создаете компонент Button и используете его везде:

<Button>Нажми меня</Button>
<Button>Отправить</Button>
<Button>Скачать</Button>

Изменив компонент Button один раз, вы измените все кнопки на сайте!

Parallax.tsx — Эффект параллакса

components/animation/Parallax.tsx

Что это? Параллакс — это когда элемент двигается с другой скоростью при прокрутке, создавая эффект глубины.

Как использовать:

import ParallaxItem from "@/components/animation/Parallax";
import Image from "next/image";

<ParallaxItem speed={0.6}>
  <Image src="/img/background.webp" alt="Фон" width={1920} height={1080} />
</ParallaxItem>

💡 Параметр speed:

  • speed={0} — элемент статичный, не двигается
  • speed={0.5} — двигается медленнее прокрутки (создает глубину)
  • speed={1} — двигается синхронно с прокруткой
  • speed={1.5} — двигается быстрее прокрутки

✅ Как настроить:

Чем меньше значение speed (0.3-0.6), тем сильнее эффект "отставания" и глубины. Экспериментируйте!

RevealText.tsx — Анимация появления текста

components/animation/RevealText.tsx

Что это? Текст появляется посимвольно при прокрутке до него.

Как использовать:

import RevealText from "@/components/animation/RevealText";

<RevealText as="h2" className="hero__title">
  Frontend Developer
</RevealText>

💡 Параметр as:

Это полиморфный компонент — может рендериться как любой HTML тег:

  • as="h1" — заголовок первого уровня
  • as="h2" — заголовок второго уровня
  • as="p" — параграф
  • as="span" — строковый элемент

VelocityMarquee.tsx — Бегущая строка

components/animation/VelocityMarquee.tsx

Что это? Бесконечная горизонтальная прокрутка элементов. Скорость зависит от скорости прокрутки страницы.

Как использовать:

import VelocityMarquee from "@/components/animation/VelocityMarquee";

<VelocityMarquee duration={20} direction="left">
  <div className="item">Элемент 1</div>
  <div className="item">Элемент 2</div>
  <div className="item">Элемент 3</div>
</VelocityMarquee>
Параметр Описание По умолчанию
duration Базовая длительность анимации (секунды) 20
direction Направление: "left" или "right" "left"
pauseOnHover Останавливать при наведении мыши false

🎓 Что такое JSON?

JSON (JavaScript Object Notation) — это текстовый формат для хранения данных. Представьте его как таблицу Excel, но в текстовом виде.

Пример:

{
  "name": "Иван",
  "age": 25,
  "skills": ["JavaScript", "React", "Next.js"]
}

Основные правила:

  • Всё в фигурных скобках { }
  • Название поля в кавычках: "name"
  • После названия двоеточие: :
  • Текст обязательно в двойных кавычках: "Иван"
  • Массивы в квадратных скобках: [ ]
  • Между элементами запятая, после последнего — НЕТ!

lib/schemas/contact.ts — Схема валидации формы

lib/schemas/contact.ts

Этот файл определяет правила валидации для контактной формы с помощью библиотеки Zod.

Код схемы:

import { z } from "zod";

export const contactSchema = z.object({
  Name: z.string().min(2, "Имя должно содержать минимум 2 символа"),
  Company: z.string().optional(),
  "E-mail": z.string().email("Некорректный email адрес"),
  Phone: z.string().optional(),
  Message: z.string().min(5, "Сообщение слишком короткое"),
});

export type ContactForm = z.infer<typeof contactSchema>;

🎓 Что такое Zod?

Zod — это библиотека для валидации данных в TypeScript.

Основные методы:

  • z.string() — строка
  • .min(5) — минимум 5 символов
  • .max(100) — максимум 100 символов
  • .email() — проверка формата email
  • .optional() — поле необязательное
  • z.number() — число
  • z.boolean() — булево значение

Как это работает:

  1. Вы описываете правила в схеме Zod
  2. React Hook Form использует эту схему
  3. При вводе данных форма проверяет их на соответствие правилам
  4. Если данные невалидны — показывается ошибка

✅ Как изменить валидацию формы:

Пример 1: Сделать поле "Телефон" обязательным

Phone: z.string().min(10, "Введите корректный телефон"),  // Было optional()

Пример 2: Добавить новое поле "Тема сообщения"

export const contactSchema = z.object({
  Name: z.string().min(2, "Имя должно содержать минимум 2 символа"),
  Company: z.string().optional(),
  "E-mail": z.string().email("Некорректный email адрес"),
  Phone: z.string().optional(),
  Subject: z.string().min(3, "Укажите тему"),  // ← Новое поле
  Message: z.string().min(5, "Сообщение слишком короткое"),
});

Пример 3: Изменить сообщения об ошибках

Name: z.string().min(2, "Слишком короткое имя, введите полное"),
"E-mail": z.string().email("Это не похоже на email адрес"),

После изменения схемы: Не забудьте добавить новое поле в форму в components/homes/home-1/Contact.tsx!

PortfolioContext.tsx — Управление модальным окном

Этот файл создает глобальное состояние для управления модальным окном портфолио.

🎓 Что такое React Context?

Context — это способ передачи данных через дерево компонентов без необходимости передавать props на каждом уровне.

Аналогия: Представьте, что Context — это Wi-Fi роутер. Вместо того, чтобы тянуть кабель к каждому устройству (передавать props), вы создаете роутер (Context), и все устройства (компоненты) могут к нему подключиться.

Когда использовать Context:

  • Данные нужны многим компонентам на разных уровнях
  • Тема оформления (светлая/темная)
  • Информация о текущем пользователе
  • Состояние модальных окон
  • Язык интерфейса

Как работает PortfolioContext:

// 1. Создание контекста
const PortfolioContext = createContext<PortfolioContextType | undefined>(undefined);

// 2. Провайдер оборачивает приложение (в app/layout.tsx)
export function PortfolioProvider({ children }) {
  const [selectedPortfolio, setSelectedPortfolio] = useState(null);

  return (
    <PortfolioContext.Provider value={{ selectedPortfolio, setSelectedPortfolio }}>
      {children}
    </PortfolioContext.Provider>
  );
}

// 3. Хук для удобного использования
export function usePortfolio() {
  const context = useContext(PortfolioContext);
  if (!context) {
    throw new Error("usePortfolio must be used within PortfolioProvider");
  }
  return context;
}

Использование в компонентах:

// В галерее портфолио
import { usePortfolio } from "@/contexts/PortfolioContext";

function Portfolios() {
  const { setSelectedPortfolio } = usePortfolio();

  const openModal = (item) => {
    setSelectedPortfolio(item);  // Открыть попап с этой работой
  };

  return (
    <div onClick={() => openModal(portfolioItem)}>
      {/* ... */}
    </div>
  );
}

// В модальном окне
function PortfolioPopup() {
  const { selectedPortfolio, setSelectedPortfolio } = usePortfolio();

  const closeModal = () => {
    setSelectedPortfolio(null);  // Закрыть попап
  };

  if (!selectedPortfolio) return null;

  return (
    <div className="popup">
      <button onClick={closeModal}>Закрыть</button>
      <h2>{selectedPortfolio.title}</h2>
      {/* ... */}
    </div>
  );
}

💡 Дополнительная логика в контексте:

Context также добавляет/удаляет класс popup-active на элемент <html>, когда попап открыт. Это позволяет CSS заблокировать прокрутку страницы:

html.popup-active {
  overflow: hidden;  /* Запретить прокрутку */
}

✅ Как создать свой Context:

Например, создадим контекст для управления языком интерфейса:

  1. Создайте файл contexts/LanguageContext.tsx
"use client";
import { createContext, useContext, useState } from "react";

type Language = "ru" | "en";

type LanguageContextType = {
  language: Language;
  setLanguage: (lang: Language) => void;
};

const LanguageContext = createContext<LanguageContextType | undefined>(undefined);

export function LanguageProvider({ children }: { children: React.ReactNode }) {
  const [language, setLanguage] = useState<Language>("ru");

  return (
    <LanguageContext.Provider value={{ language, setLanguage }}>
      {children}
    </LanguageContext.Provider>
  );
}

export function useLanguage() {
  const context = useContext(LanguageContext);
  if (!context) {
    throw new Error("useLanguage must be used within LanguageProvider");
  }
  return context;
}
  1. Добавьте провайдер в app/layout.tsx:
import { LanguageProvider } from "@/contexts/LanguageContext";

<LanguageProvider>
  <PortfolioProvider>
    {children}
  </PortfolioProvider>
</LanguageProvider>
  1. Используйте в компонентах:
import { useLanguage } from "@/contexts/LanguageContext";

function Header() {
  const { language, setLanguage } = useLanguage();

  return (
    <button onClick={() => setLanguage(language === "ru" ? "en" : "ru")}>
      {language === "ru" ? "EN" : "RU"}
    </button>
  );
}

🎯 Ключевые паттерны и концепции

1. Server Components vs Client Components

🎓 Когда использовать Server Components:

  • Страницы без интерактивности
  • Компоненты, которые только отображают данные
  • Компоненты, которым нужен доступ к базе данных (в этом проекте не используется)

Пример: Страница в app/(homes)/home-1/page.tsx — это Server Component.

🎓 Когда использовать Client Components:

  • Нужны хуки React (useState, useEffect, useRef)
  • Обработка событий (onClick, onChange)
  • Использование браузерных API (localStorage, window, IntersectionObserver)
  • Анимации (GSAP требует доступ к DOM)

Пример: Все компоненты в components/ — это Client Components с директивой "use client".

2. Паттерн "Данные в JSON"

Проект четко разделяет данные и представление:

Данные (что показывать) Представление (как показывать)

data/services.json components/homes/home-1/Services.tsx

✅ Преимущества этого подхода:

  • Менять контент = менять только JSON, не трогая код
  • Легко добавлять новые языки (создать data-en/ папку)
  • Контент-менеджер может редактировать JSON без знания React
  • Можно легко подключить CMS в будущем

3. Полиморфные компоненты

Компоненты вроде RevealText и HoverCursorEffect могут рендериться как любой HTML элемент.

// Может быть заголовком
<RevealText as="h1">Заголовок</RevealText>

// Может быть параграфом
<RevealText as="p">Текст</RevealText>

// Может быть ссылкой
<HoverCursorEffect as="a" href="#contact">Контакт</HoverCursorEffect>

💡 Как это работает?

Используются TypeScript Generics и ComponentPropsWithoutRef для типобезопасности:

type Props<T extends ElementType> = {
  as?: T;
  children: ReactNode;
} & ComponentPropsWithoutRef<T>;

4. GSAP Анимации - Правильный подход

Всегда используйте cleanup:

useLayoutEffect(() => {
  const ctx = gsap.context(() => {
    // Ваши анимации
    gsap.to(element, { ... });
  }, containerRef);

  return () => ctx.revert();  // ← ВАЖНО! Очистка при размонтировании
}, []);

Используйте useLayoutEffect для анимаций:

useLayoutEffect выполняется синхронно после изменений DOM, но до отрисовки браузера. Это предотвращает "мигание" элементов.

Обновление ScrollTrigger при изменении контента:

const handleRefresh = () => {
  // Перестроить анимации при изменении размера/контента
};

ScrollTrigger.addEventListener("refresh", handleRefresh);
return () => ScrollTrigger.removeEventListener("refresh", handleRefresh);
