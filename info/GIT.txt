📝 Как закоммитить проект в Git

  Шаг 0: Проверим наличие .gitignore, если нет то создаём и настраиваем правильно.

  Шаг 1: Инициализируйте Git репозиторий

  Откройте терминал в папке проекта и выполните:

  git init

  Это создаст скрытую папку .git с историей версий.

  ---
  Шаг 2: Проверьте, что будет добавлено

  git status

  Вы увидите все файлы, которые Git готов отслеживать. Красным цветом будут показаны неотслеживаемые файлы.

  Что НЕ будет закоммичено (благодаря .gitignore):
  - ❌ node_modules/ — зависимости (скачаются при npm install)
  - ❌ .next/ — build файлы Next.js
  - ❌ .env файлы — секретные ключи
  - ❌ .DS_Store — системные файлы Mac

  Что БУДЕТ закоммичено:
  - ✅ Исходный код (app/, components/, contexts/, lib/)
  - ✅ Данные (data/)
  - ✅ Статические файлы (public/)
  - ✅ Конфигурационные файлы (package.json, tsconfig.json, next.config.ts)
  - ✅ Документация (info/)

  ---
  Шаг 3: Добавьте все файлы в staging

  git add .

  Это подготовит все файлы к коммиту.

  Или добавьте файлы выборочно:
  git add app/ components/ data/ public/ package.json

  🤖 Generated with Claude Code

  Шаг 5 (Опционально): Подключите к GitHub

  5.1 Создайте репозиторий на GitHub

  1. Зайдите на https://github.com
  2. Нажмите New repository
  3. Назовите: blayden-portfolio или my-portfolio
  4. НЕ выбирайте "Initialize with README" (у вас уже есть код)
  5. Создайте репозиторий

  5.2 Свяжите локальный проект с GitHub

  GitHub покажет команды, но вот готовые:

  # Добавьте удаленный репозиторий (замените YOUR-USERNAME и REPO-NAME)
  git remote add origin https://github.com/YOUR-USERNAME/REPO-NAME.git

  # Переименуйте ветку в main (если нужно)
  git branch -M main

  # Загрузите код на GitHub
  git push -u origin main

  ---
  🔄 Работа с Git дальше

  Проверить статус

  git status

  Посмотреть изменения

  git diff

  Добавить изменённые файлы

  git add .
  # или конкретные файлы
  git add data/portfolios.json components/homes/home-1/Hero.tsx

  Создать коммит

  git commit -m "Описание изменений"

  Загрузить на GitHub

  git push

  Посмотреть историю

  git log --oneline

  ---
  💡 Полезные команды

  Отменить изменения в файле (до коммита)

  git checkout -- имя-файла.tsx

  Отменить последний коммит (оставить изменения)

  git reset --soft HEAD~1

  Создать новую ветку

  git checkout -b feature/add-video-support

  Переключиться на ветку

  git checkout main

   А почему создалась ветка master а не main?

  ● Отличный вопрос! Это связано с настройками Git на вашем компьютере.

    📖 Почему создалась ветка master?

    Историческая справка:
    - До 2020 года: Git по умолчанию создавал ветку master
    - С 2020 года: GitHub и другие платформы перешли на main как дефолтное название (из-за инклюзивности)
    - Ваш локальный Git: всё ещё использует старую конфигурацию и создаёт master

    🔧 Как переименовать ветку в main

    Вариант 1: Переименовать текущую ветку

    git branch -M main

    Флаг -M = "move" (переименовать) с перезаписью.

    Вариант 2: Настроить Git глобально (на будущее)

    Чтобы Git всегда создавал main вместо master:

    git config --global init.defaultBranch main

    Теперь при каждом git init будет создаваться ветка main.

    ---
    ✅ Что делать сейчас

    Выполните обе команды:

    # 1. Переименовать текущую ветку master → main
    git branch -M main

    # 2. Настроить Git для будущих проектов
    git config --global init.defaultBranch main

    # 3. Проверить что ветка переименована
    git branch

    Теперь при git push на GitHub не будет конфликта (GitHub ждёт main).

    ---
    🤔 В чём разница между master и main?

    Технически: НИКАКОЙ разницы нет. Это просто название.

    Практически:
    - main — современный стандарт (GitHub, GitLab, Bitbucket)
    - master — старое название (всё ещё работает, но deprecated)

    Рекомендация: Используйте main для новых проектов, чтобы соответствовать современным стандартам.

    # Показать с подробностями
    git status

    Глобальные настройки (git config --global init.defaultBranch main) можно делать из папки проэкта или нужно переходить в
    корень диска?

    ● Отличный вопрос!

      📍 Где выполнять git config --global?

      Ответ: Абсолютно не важно!

      Можно выполнять из любой папки — хоть из папки проекта, хоть из корня диска, хоть из любого места на компьютере.

      ---
      🎯 Почему так?

      Флаг --global означает:

      Настройка сохраняется в глобальный конфигурационный файл пользователя, а не в текущую папку.

      Где хранится:
      - Windows: C:\Users\ВашеИмя\.gitconfig
      - Linux/Mac: ~/.gitconfig

      Этот файл применяется ко всем Git репозиториям на вашем компьютере.

      ---
      📊 Уровни конфигурации Git

      Git имеет 3 уровня настроек:

      | Уровень | Команда               | Где хранится   | Область действия                      |
      |---------|-----------------------|----------------|---------------------------------------|
      | System  | --system              | /etc/gitconfig | Все пользователи компьютера           |
      | Global  | --global              | ~/.gitconfig   | Все репозитории текущего пользователя |
      | Local   | --local или без флага | .git/config    | Только текущий репозиторий            |

      ---
      💡 Примеры

      Global настройки (из любой папки):

      # Можно из папки проекта
      cd "D:\3. My Projects\3.Front-end\Nexst.JS\1.blayden\blayden"
      git config --global init.defaultBranch main

      # Можно из корня диска
      cd D:\
      git config --global init.defaultBranch main

      # Можно даже из рабочего стола
      cd C:\Users\ВашеИмя\Desktop
      git config --global init.defaultBranch main

      # Результат одинаковый! ✅

      Local настройки (только внутри репозитория):

      # Должны быть ВНУТРИ Git репозитория
      cd "D:\3. My Projects\3.Front-end\Nexst.JS\1.blayden\blayden"
      git config --local user.name "Специальное имя только для этого проекта"

      ---
      🔍 Проверка настроек

      Посмотреть все глобальные настройки:

      git config --global --list

      Посмотреть конкретную настройку:

      git config --global init.defaultBranch

      Посмотреть где хранится:

      git config --global --list --show-origin

      ---
      ✅ Вывод

      Выполняйте git config --global откуда удобно — можете прямо из папки проекта, не нужно никуда переходить!

      # Всё это можно делать прямо из папки вашего проекта:
      git config --global init.defaultBranch main
      git config --global user.name "Ваше Имя"
      git config --global user.email "your.email@example.com"

      Настройки сохранятся глобально и будут работать для всех будущих проектов. 🎉
